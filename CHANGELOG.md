# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The project follows [Semantic Versioning](https://semver.org/), with the 0.x caveat that the public API may change.

This repository is the Go implementation of Forgebase ([ADR 0026](docs/adr/0026-go-implementation.md)). The changelog of the Rust implementation, up to M10, is in the frozen repository <https://github.com/tvstore/Forgebase>.

## [Unreleased]

### Added

- **P3.1 Authentication storage, the list query, link titles and the `user`, `token` and `doc list` commands (`internal/db`, `internal/httpapi`, `internal/app`).** Ported from the Rust crates `forgebase-db`, `forgebase-http` and `forgebase`: `auth.go` (users, roles, Argon2id passwords, sessions with CSRF tokens, API tokens, the login lockout, the user permissions loaded with the roles on every `ValidateSession` and `ValidateAPIToken`, the purge functions of expired sessions and login failures), `user_permissions.go` (`AddUserPermission`, `RemoveUserPermission`, `ListUserPermissions` with the cap of 1000 documents per DocType), `list.go` (`List`, `ListQuery`, `Filter`, `FilterOp`, `Sort`, `ColumnType`, the limits 20, 500 and 500; every operator is checked against the field type and every value is a bound parameter) and `link_titles.go` (`LinkTitles`, under the caller's read rules). The filter and sort parsing of the list (`ParseFilters`, `ParseSort`, `CheckFiltersSyntax`, the other half of `json.rs`) is in `internal/httpapi`, shared by the command line and, from P3.2, the HTTP API.
  - New commands, no longer refused with "not available yet": `forgebase doc list DOCTYPE [--filter JSON] [--sort FIELD[:desc]]... [--limit N] [--offset N]` (a pretty JSON array, as the Rust binary prints it), `forgebase user create|set-password|add-role|remove-role|disable|enable` (the password is the first line of standard input, at most 4096 bytes, never an argument and never printed) and `forgebase token create|revoke` (`create` prints `key:secret` once). `user permission` stays in P7, `serve` in P3.2. The text of every success line and error is the Rust one.
  - **Passwords are byte-compatible with the Rust implementation.** A hash is `$argon2id$v=19$m=19456,t=2,p=1$<salt>$<hash>` (16-byte salt, 32-byte output, base64 without padding), verified with the parameters inside the stored string. A test pins our hash of a fixed password and salt to the string written by the reference C implementation (argon2-cffi), and checks that strings written by that implementation, with our parameters and with others, verify here: a hash written by either implementation verifies in the other. Known difference: a stored hash that the Go Argon2 implementation cannot run (version `v=16`, more than 255 lanes) is not verified, so the login fails like a wrong password; Forgebase writes none of those. Argon2 runs in the calling goroutine, so it blocks no other goroutine (Rust uses `spawn_blocking`).
  - New dependency: `golang.org/x/crypto` v0.58.0 (BSD-3-Clause; only the `argon2` and `blake2b` packages are linked), approved by the owner as G2. It needs `golang.org/x/sys` (BSD-3-Clause, `cpu` feature detection) and raised the indirect `golang.org/x/sync` (v0.22.0 to v0.24.0) and `golang.org/x/text` (v0.41.0 to v0.43.0) that `pgx` already pulled in; see the [dependency evaluation](docs/blueprint/dependency-evaluation.md). `govulncheck` reports GO-2026-5932 (the unmaintained `x/crypto/openpgp` package) as a vulnerability in a required module that the code does not call.
  - New in `db.Error`: `ErrInvalidQuery` (`invalid list query: ...`). New `db.AuthError` with a `Kind` for every variant of the Rust `AuthError` (`AuthInvalidCredentials` ... `AuthDB`), the same texts; a database error is an `AuthError` that wraps the `*db.Error`. `LoginSession` and `APITokenSecret` print their secrets as `<redacted>` with every `fmt` verb. New in `core`: `DebugQuote`, the Rust `{:?}` of a string, for the messages of the list.
  - Tests: `auth.rs`, `list.rs`, `link_titles.rs` and `read_only.rs` (all of them), the `user_permissions.rs` tests that were deferred for auth, the management of user permissions, the list and the link titles (`the_permissions_are_loaded_with_every_authenticated_request`, `adding_checks_the_user_the_doctype_the_value_and_the_document`, `the_list_is_sorted_and_filtered`, `a_user_has_at_most_a_thousand_documents_per_doctype`, `a_database_without_the_table_still_serves_its_users`, `link_titles_leave_out_hidden_targets` and the list parts of `every_read_shows_only_what_the_restriction_allows`, `a_caller_without_the_read_right_is_denied_before_any_scope` and `a_hidden_link_field_still_restricts_and_its_value_is_not_revealed`), the list parts of `permissions.rs` and `field_levels.rs` that P2.1 deferred, the unit tests of `auth.rs` and `list.rs`, and from `cli.rs` `list_filters_sorts_and_pages_as_json`, `user_commands_manage_users_and_roles`, `token_create_prints_the_secret_once_and_revoke_works`, the list cases of `malformed_json_and_filters_fail_before_the_database_is_used` and the `user` and `token` parts of `sites.rs`; each with a `// Rust: file::test` comment. Added in Go: the PHC compatibility tests, the tests of the purge functions (Rust tests them in `schedule.rs`, P5) and of the filter and sort parsing. Deferred with their phase: the group-by and aggregate parts of the field-level tests and the summary parts of `user_permissions.rs` (P6, with `summary`), everything that calls `export`, `import` or the saved views (P6, P7), the transitions (P6), `two_sites_keep_their_own_permissions` (P5) and `serve_*` (P3.2).
- **P2.2 The command-line skeleton of the Go port (`cmd/forgebase`, `internal/app`).** The stock `forgebase` binary (no apps; DocTypes from `--doctypes DIR`) now has `--version`/`-V`, `--help`/`-h` at every level, `migrate` and `doc insert|get|update|delete|submit|cancel|amend`, on the implicit `default` site (`FORGEBASE_DATABASE_URL`) and on a site of a `forgebase.toml` (`--config`, `FORGEBASE_CONFIG`, `--site`), with the same flags, defaults, ranges, help texts (the doc comments of the Rust `args.rs`), usage errors with exit code 2, error texts, exit codes and JSON output (pretty, sorted keys) as the Rust binary.
  - The argument parser is written for this project (`internal/app/cli.go`, `cli_help.go`, the command tree in `cli_commands.go`, standard library only, no command-line framework, ADR 0026 G2). It reproduces clap 4 as the Rust binary is built (derive, without `wrap_help`, `color` and `suggestions`): `Usage:`, `Commands:`, `Arguments:` and `Options:` sections, `[default: ...]` and `[possible values: ...]`, the short and the long help (`-h`, `--help`, `help SUBCOMMAND`), `global` options before or after the subcommand, `error: unexpected argument ... found` with the `--` tip, `unrecognized subcommand`, `the following required arguments were not provided:`, `invalid value ... for ...`, `a value is required for ...`, the help on standard error with code 2 for a command without its subcommand. Help and version end the parse where they are met, as in clap (so `forgebase --version extra` prints the version; the P0 skeleton refused it).
  - Known differences from clap (listed in the [CLI guide](docs/guide/cli.md#parity-with-the-rust-command-line)): the wording and order of the usage line of an error that follows optional arguments, the order of the global options among a subcommand's own in `--help`, and the blank lines inside a long-help description are written from the clap 4 source as remembered, with no clap binary to compare against in this repository (no test asserts more than the substrings the Rust tests assert).
  - **The only intended difference in behaviour:** a command that is not ported yet (`serve` in P3; `new-app` in P4; `worker`, `job`, `site` in P5; `doc transition` in P6; `data`, `webhook`, `customize` and `user permission` in P7) is parsed completely (so its help and its usage errors are those of the Rust binary) and then fails with exit code 1 and `error: <command> is not available yet in the Go port (arrives in phase P<n>)`. The line goes away as each command lands.
  - Not yet in `migrate`, because they need the app model and the job queue: the app data migrations, the `schedules:` and `fixtures:` lines, the warning about apps that are recorded in the database but not installed (P4, P5); the workflow backfill (P6); the site's custom fields in the registry (P7). On a first `migrate` the Rust binary also prints the schedules of its built-in clean-up jobs; the Go binary does so from P5.
  - New in `internal/db`: `Migrate`, `MigrateReport` (the composition of the framework migrations and the schema sync under one session-level advisory lock on a connection taken out of the pool; the Rust `migrate` of `forgebase-db`), with the test `schema_sync::migrate_runs_migrations_then_sync` that P1.2 deferred. New in `internal/httpapi`: `IsWellformedHost` and the input half of `json.rs` (`ParseInput`, `CheckInputSyntax`, `Input`, `JSONError`), which the CLI and, from P3, the HTTP API share.
  - Tests ported from `crates/forgebase/tests/cli.rs` (`version_and_usage_errors`, `the_stock_binary_without_doctypes_is_a_usage_error_that_names_the_subcommand`, `missing_database_url_is_a_clear_error`, `dry_run_creates_nothing`, `migrate_creates_tables_and_a_rerun_changes_nothing`, `insert_get_update_delete`, `insert_reads_data_from_standard_input_with_default_actor`, `validation_errors_exit_1_with_one_message_per_line`, `bad_input_and_unique_violations_exit_1`, `schema_conflicts_exit_1_and_change_nothing`, `invalid_doctype_files_exit_1_naming_the_file`, `links_and_versions_end_to_end`, `unknown_link_targets_are_reported_with_the_file`, `child_tables_end_to_end`, `submit_cancel_and_amend_end_to_end` and the doc part of `malformed_json_and_filters_fail_before_the_database_is_used`), from `sites.rs` (the parts that use `migrate` and `doc`), and the unit tests of `config.rs`, `doctypes.rs`, `report.rs`, `error.rs` and of the input half of `json.rs`; each with a `// Rust: file::test` comment. The DocType fixture directory of the Rust CLI tests is copied byte-identical to `internal/app/testdata/quickstart`. Tests run in process (`internal/app`) and, for exit codes and standard input, against the built binary (`cmd/forgebase`). Deferred with their phase: the tests of the commands that are not ported (`doc list`, `user`, `token`, `serve`, `worker`, `job`, `site`, `doc transition`, `webhook`, `data`, `customize`, `user permission`), the unit tests of `documents.rs` and `compose.rs` that need apps, jobs or reports (P4 to P6), and `run.rs::*` of `serve` (P3).
- **P2.1 The document pipeline of the Go port (`internal/db`).** Ported from the Rust crate `forgebase-db`: `Insert`, `Get`, `Update`, `Delete`, `Submit`, `Cancel` and `Amend` (every one in its own transaction, or a savepoint inside the `pgx.Tx` the caller passes; the same lifecycle-hook order, row locks, optimistic concurrency, error kinds and error texts), Link resolution with `FOR KEY SHARE` and the read check on the target, child tables, the read scope in SQL (`if_owner` and user permissions), field levels (`checkInput`, `redact`, `scrub`), gapless naming series in `fb_series`, the docstatus rules and the workflow columns (`WorkflowRequired`, the state written on insert and amend, `EditDenied`), the outbox (`Enqueue`, the jobs hooks enqueue and the webhook deliveries, all written in the operation's transaction) and the JSON form of a document (`DocumentToJSON`). The `pipeline`, `updateTail`, `submitTail` and `cancelTail` pieces that the workflow transitions continue in (P6) are in place. The value binding and decoding of `value.rs` (explicit casts, `Datetime` cut to microseconds like the Rust `time` crate, `Decimal` through numeric text so that a scale is kept) is in `value.go`.
  - New dependency: `github.com/google/uuid` v1.6.0 (BSD-3-Clause, no dependencies of its own) for the UUID v7 ids; see the [dependency evaluation](docs/blueprint/dependency-evaluation.md).
  - New error kinds in `db.Error` (the Rust `DbError` variants the pipeline needs): `ErrUnknownDocType`, `ErrChildDocType`, `ErrChangedWhileReading`, `ErrValidation`, `ErrNotFound`, `ErrConflict`, `ErrLinkedDocumentExists`, `ErrPermissionDenied`, `ErrUniqueViolation`, `ErrInvalidActor`, `ErrNaming`, `ErrDecode`, `ErrNoChanges`, `ErrInvalidDocStatus`, `ErrNotSubmittable`, `ErrFieldLocked`, `ErrAlreadyAmended`, `ErrWorkflowRequired`, `ErrEditDenied`, `ErrJob`, `ErrHook`.
  - Tests: `documents`, `links`, `child_tables`, `lifecycle`, `docstatus`, `series` and `concurrency`, the parts of `docstatus_schema` that P1.2 had replaced with SQL, the parts of `permissions`, `field_levels` and `user_permissions` that only use get, insert, update, delete, submit, cancel and amend, the outbox tests of `jobs` and `webhooks`, and the unit tests of `value.rs`, `scope.rs` and `document.rs`, each with a `// Rust: file::test` comment. Deferred with their phase: everything that calls `list`, `summary`, `export`, `link_titles` or `import` (P3, P7), the transitions (P6), the queue functions of `jobs.rs` (P5) and the webhook management of `webhooks.rs` (P7).
  - Differences from Rust, for the parity report: `Get` returns `nil, nil` for a document that is not there (Rust `Option`); a Go `Document` is copied before the hooks see it (Rust moves it) and `BeforeDelete` and `BeforeCancel` get a fresh copy per hook, because Go cannot pass a read-only reference; `StoredDocument` has `AmendedFrom` and `WorkflowState` as strings where `""` is none, and `DocStatus` as a pointer; the texts of `ErrDecode` and of the NULL or infinite timestamp of a stored row are hand-written (tokio-postgres says "error deserializing column ..."), and so is the bind error "cannot bind a … value as …" (tokio-postgres: "cannot convert between the Rust type … and the Postgres type …"), which validation makes unreachable in practice; `ErrUniqueViolation` and `ErrLinkedDocumentExists` keep no driver error (Rust holds none), so a hidden field or DocType cannot leak through `errors.As`.
- **P1.2 The database foundations of the Go port (`internal/db`).** Ported from the Rust crate `forgebase-db`: the connection pool (`Connect`, `ConnectSized`: four connections per CPU, no TLS until P5, other `sslmode` values and `sslrootcert` refused, no URL or password in any error), the error type (`db.Error` with a `Kind`, the same message texts, SQLSTATE handling: `55P03` is `ErrLockTimeout`), `QuoteIdent`, the 13 framework migrations (the SQL files are byte-identical to the Rust ones, embedded with `go:embed`; same advisory lock, same bootstrap SQL, checksum computed by PostgreSQL, `ErrUnknownMigration`, `ErrChecksumMismatch`, dry run), and the additive DocType schema sync (`Sync`, `SyncOptions`, `SyncReport`, `Step`, `Conflict`, `Warning` with the same texts and the same generated SQL, so a schema created by one implementation is accepted by the other).
  - New package `internal/db/dbtest`: one throwaway `fb_test_*` database per test from `FORGEBASE_TEST_DATABASE_URL`, dropped with `FORCE` at cleanup; a missing variable fails the test.
  - The tests of `framework_migrations.rs`, `schema_sync.rs`, `docstatus_schema.rs` and the unit tests of `ident.rs`, `plan.rs` and `migrate.rs` are ported (a `// Rust: file::test` comment each); a test pins the SHA-256 of every migration file to the value of the Rust files.
  - New dependency: `github.com/jackc/pgx/v5` v5.12.0 (MIT) with its transitive modules `pgpassfile`, `pgservicefile`, `puddle/v2` (MIT), `golang.org/x/sync` and `golang.org/x/text` (BSD-3-Clause); see the [dependency evaluation](docs/blueprint/dependency-evaluation.md). `github.com/google/uuid` is not needed yet and is admitted in P2.1.
  - The database URL is the only source of connection settings, as with `tokio-postgres`: the `PG*` variables and `~/.pgpass` have no effect, unknown URL keys are refused, and a set `PGSERVICE` is refused with an error (a disclosed deviation: Rust ignores it, and `pgx` cannot be told to), and the pool has no connection lifetime limit (like `deadpool-postgres`). `SyncOptions.LockTimeout` is used as given and clamped to 1 ms to `i32::MAX` ms like Rust (zero is 1 ms); `DefaultSyncOptions()` is the 5 s default.
  - Not in P1.2: `CreateDatabase` and `RecordedApps` (they come with the sites in P5, with TLS), the value binding and decoding of `value.rs` (done in P2.1, with the document operations), `Migrate` (the composition with app migrations, schedules, workflow backfill and fixtures, P2 and later).
- **P1.1 The core of the Go port (`internal/core`).** The whole of the Rust crate `forgebase-core` is ported: identifier rules, the DocType model and its validation (every rule and every message text of `DefinitionError`), the registry with owners, hooks, jobs, reports and methods, TOML loading of DocTypes, overlays and custom fields, documents and their validation (child tables included), naming series, the workflow definition, the permission evaluator (rights, `if_owner`, field levels, user permissions and the row scope), query report and app method definitions, and lifecycle hooks as an interface with a no-op base struct (`core.BaseHooks`). All 177 Rust unit and integration tests are ported with a `// Rust: file::test` comment each.
  - New package `internal/decimal`: a `rust_decimal`-compatible fixed-point number (96-bit mantissa, scale 0 to 28, the same accepted text forms, rounding and error messages), tested with the vectors of the `rust_decimal` 1.43.0 test suite.
  - New dependency: `github.com/BurntSushi/toml` v1.6.0 (MIT, no dependencies of its own); `go.sum` is committed. [ADR 0027](docs/adr/0027-decimal-and-toml.md) records this and the decimal decision.
  - Known differences from Rust (for the parity report): the wording of TOML and JSON parse errors (the key is named; serde's wording without the line excerpt; every input that Rust refuses as a parse error is refused, tested case by case, with the same error kind); a field given as JSON must be decoded with `UseNumber` or Go integers (a float is refused for an integer key, as serde_json does).
- **P0 Foundations of the Go port (ADR 0026).**
  - The Go module `github.com/tvstore/forgebase-go` (`go 1.26.0`, `toolchain go1.27.3`, no dependencies) with the root package `forgebase` (`Version = "0.0.0"`), the `internal/core`, `internal/db`, `internal/httpapi` and `internal/app` packages (documentation only; the import direction is stated in each), and the placeholder package `forgebase/testing`.
  - `forgebase --version` and `forgebase -V` print `forgebase 0.0.0`; any other command prints a usage to standard error and exits with status 2.
  - CI (`.github/workflows/ci.yml`): the jobs `changes` (path classifier with the key `go`, unit-tested), `docs` (offline link check), `check` (gofmt, `go vet`, staticcheck v0.8.2, govulncheck v1.9.0, `go test -race`, `go build`, `go mod verify`, `go mod tidy -diff`, with a PostgreSQL 16 service), `licenses` (a standard-library licence checker, `.github/ci/licensecheck`) and `ci-result`. Go is installed from the official tarball with a verified sha256 (`.github/ci/install-go.sh`); no setup action is used. Module, build and tool caches use `actions/cache`.
  - `ci-result` **fails on a draft pull request** with a clear message, so that a draft run can never satisfy the required check (G8). The workflow also runs on `converted_to_draft`.
  - Documentation carried over from the Rust repository: `AGENTS.md` (adapted to Go), `docs/owner-decisions.md` (with the Go port decisions G1 to G8), the blueprint, the guides (with a note that code examples still show the Rust API until their phase), ADRs 0001 to 0025 unchanged, the new [ADR 0026](docs/adr/0026-go-implementation.md), `README.md`, `CONTRIBUTING.md` and the assets (with a Go badge).
