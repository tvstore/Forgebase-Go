# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The project follows [Semantic Versioning](https://semver.org/), with the 0.x caveat that the public API may change.

This repository is the Go implementation of Forgebase ([ADR 0026](docs/adr/0026-go-implementation.md)). The changelog of the Rust implementation, up to M10, is in the frozen repository <https://github.com/tvstore/Forgebase>.

## [Unreleased]

### Added

- **P2.1 The document pipeline of the Go port (`internal/db`).** Ported from the Rust crate `forgebase-db`: `Insert`, `Get`, `Update`, `Delete`, `Submit`, `Cancel` and `Amend` (every one in its own transaction, or a savepoint inside the `pgx.Tx` the caller passes; the same lifecycle-hook order, row locks, optimistic concurrency, error kinds and error texts), Link resolution with `FOR KEY SHARE` and the read check on the target, child tables, the read scope in SQL (`if_owner` and user permissions), field levels (`checkInput`, `redact`, `scrub`), gapless naming series in `fb_series`, the docstatus rules and the workflow columns (`WorkflowRequired`, the state written on insert and amend, `EditDenied`), the outbox (`Enqueue`, the jobs hooks enqueue and the webhook deliveries, all written in the operation's transaction) and the JSON form of a document (`DocumentToJSON`). The `pipeline`, `updateTail`, `submitTail` and `cancelTail` pieces that the workflow transitions continue in (P6) are in place. The value binding and decoding of `value.rs` (explicit casts, `Datetime` cut to microseconds like the Rust `time` crate, `Decimal` through numeric text so that a scale is kept) is in `value.go`.
  - New dependency: `github.com/google/uuid` v1.6.0 (BSD-3-Clause, no dependencies of its own) for the UUID v7 ids; see the [dependency evaluation](docs/blueprint/dependency-evaluation.md).
  - New error kinds in `db.Error` (the Rust `DbError` variants the pipeline needs): `ErrUnknownDocType`, `ErrChildDocType`, `ErrChangedWhileReading`, `ErrValidation`, `ErrNotFound`, `ErrConflict`, `ErrLinkedDocumentExists`, `ErrPermissionDenied`, `ErrUniqueViolation`, `ErrInvalidActor`, `ErrNaming`, `ErrDecode`, `ErrNoChanges`, `ErrInvalidDocStatus`, `ErrNotSubmittable`, `ErrFieldLocked`, `ErrAlreadyAmended`, `ErrWorkflowRequired`, `ErrEditDenied`, `ErrJob`, `ErrHook`.
  - Tests: `documents`, `links`, `child_tables`, `lifecycle`, `docstatus`, `series` and `concurrency`, the parts of `docstatus_schema` that P1.2 had replaced with SQL, the parts of `permissions`, `field_levels` and `user_permissions` that only use get, insert, update, delete, submit, cancel and amend, the outbox tests of `jobs` and `webhooks`, and the unit tests of `value.rs`, `scope.rs` and `document.rs`, each with a `// Rust: file::test` comment. Deferred with their phase: everything that calls `list`, `summary`, `export`, `link_titles` or `import` (P3, P7), the transitions (P6), the queue functions of `jobs.rs` (P5) and the webhook management of `webhooks.rs` (P7).
  - Differences from Rust, for the parity report: `Get` returns `nil, nil` for a document that is not there (Rust `Option`); a Go `Document` is copied before the hooks see it (Rust moves it) and `BeforeDelete` and `BeforeCancel` get a fresh copy per hook, because Go cannot pass a read-only reference; `StoredDocument` has `AmendedFrom` and `WorkflowState` as strings where `""` is none, and `DocStatus` as a pointer.
- **P1.2 The database foundations of the Go port (`internal/db`).** Ported from the Rust crate `forgebase-db`: the connection pool (`Connect`, `ConnectSized`: four connections per CPU, no TLS until P5, other `sslmode` values and `sslrootcert` refused, no URL or password in any error), the error type (`db.Error` with a `Kind`, the same message texts, SQLSTATE handling: `55P03` is `ErrLockTimeout`), `QuoteIdent`, the 13 framework migrations (the SQL files are byte-identical to the Rust ones, embedded with `go:embed`; same advisory lock, same bootstrap SQL, checksum computed by PostgreSQL, `ErrUnknownMigration`, `ErrChecksumMismatch`, dry run), and the additive DocType schema sync (`Sync`, `SyncOptions`, `SyncReport`, `Step`, `Conflict`, `Warning` with the same texts and the same generated SQL, so a schema created by one implementation is accepted by the other).
  - New package `internal/db/dbtest`: one throwaway `fb_test_*` database per test from `FORGEBASE_TEST_DATABASE_URL`, dropped with `FORCE` at cleanup; a missing variable fails the test.
  - The tests of `framework_migrations.rs`, `schema_sync.rs`, `docstatus_schema.rs` and the unit tests of `ident.rs`, `plan.rs` and `migrate.rs` are ported (a `// Rust: file::test` comment each); a test pins the SHA-256 of every migration file to the value of the Rust files.
  - New dependency: `github.com/jackc/pgx/v5` v5.12.0 (MIT) with its transitive modules `pgpassfile`, `pgservicefile`, `puddle/v2` (MIT), `golang.org/x/sync` and `golang.org/x/text` (BSD-3-Clause); see the [dependency evaluation](docs/blueprint/dependency-evaluation.md). `github.com/google/uuid` is not needed yet and is admitted in P2.1.
  - The database URL is the only source of connection settings, as with `tokio-postgres`: the `PG*` variables and `~/.pgpass` have no effect, unknown URL keys are refused, and a set `PGSERVICE` is refused with an error (a disclosed deviation: Rust ignores it, and `pgx` cannot be told to), and the pool has no connection lifetime limit (like `deadpool-postgres`). `SyncOptions.LockTimeout` is used as given and clamped to 1 ms to `i32::MAX` ms like Rust (zero is 1 ms); `DefaultSyncOptions()` is the 5 s default.
  - Not in P1.2: `CreateDatabase` and `RecordedApps` (they come with the sites in P5, with TLS), the value binding and decoding of `value.rs` (done in P2.1, with the document operations), `Migrate` (the composition with app migrations, schedules, workflow backfill and fixtures, P2 and later).
- **P1.1 The core of the Go port (`internal/core`).** The whole of the Rust crate `forgebase-core` is ported: identifier rules, the DocType model and its validation (every rule and every message text of `DefinitionError`), the registry with owners, hooks, jobs, reports and methods, TOML loading of DocTypes, overlays and custom fields, documents and their validation (child tables included), naming series, the workflow definition, the permission evaluator (rights, `if_owner`, field levels, user permissions and the row scope), query report and app method definitions, and lifecycle hooks as an interface with a no-op base struct (`core.BaseHooks`). All 177 Rust unit and integration tests are ported with a `// Rust: file::test` comment each.
  - New package `internal/decimal`: a `rust_decimal`-compatible fixed-point number (96-bit mantissa, scale 0 to 28, the same accepted text forms, rounding and error messages), tested with the vectors of the `rust_decimal` 1.43.0 test suite.
  - New dependency: `github.com/BurntSushi/toml` v1.6.0 (MIT, no dependencies of its own); `go.sum` is committed. [ADR 0027](docs/adr/0027-decimal-and-toml.md) records this and the decimal decision.
  - Known differences from Rust (for the parity report): the wording of TOML and JSON parse errors (the key is named; serde's wording without the line excerpt; every input that Rust refuses as a parse error is refused, tested case by case, with the same error kind); a field given as JSON must be decoded with `UseNumber` or Go integers (a float is refused for an integer key, as serde_json does).
- **P0 Foundations of the Go port (ADR 0026).**
  - The Go module `github.com/tvstore/forgebase-go` (`go 1.26.0`, `toolchain go1.27.3`, no dependencies) with the root package `forgebase` (`Version = "0.0.0"`), the `internal/core`, `internal/db`, `internal/httpapi` and `internal/app` packages (documentation only; the import direction is stated in each), and the placeholder package `forgebase/testing`.
  - `forgebase --version` and `forgebase -V` print `forgebase 0.0.0`; any other command prints a usage to standard error and exits with status 2.
  - CI (`.github/workflows/ci.yml`): the jobs `changes` (path classifier with the key `go`, unit-tested), `docs` (offline link check), `check` (gofmt, `go vet`, staticcheck v0.8.2, govulncheck v1.9.0, `go test -race`, `go build`, `go mod verify`, `go mod tidy -diff`, with a PostgreSQL 16 service), `licenses` (a standard-library licence checker, `.github/ci/licensecheck`) and `ci-result`. Go is installed from the official tarball with a verified sha256 (`.github/ci/install-go.sh`); no setup action is used. Module, build and tool caches use `actions/cache`.
  - `ci-result` **fails on a draft pull request** with a clear message, so that a draft run can never satisfy the required check (G8). The workflow also runs on `converted_to_draft`.
  - Documentation carried over from the Rust repository: `AGENTS.md` (adapted to Go), `docs/owner-decisions.md` (with the Go port decisions G1 to G8), the blueprint, the guides (with a note that code examples still show the Rust API until their phase), ADRs 0001 to 0025 unchanged, the new [ADR 0026](docs/adr/0026-go-implementation.md), `README.md`, `CONTRIBUTING.md` and the assets (with a Go badge).
